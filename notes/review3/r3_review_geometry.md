# Round 3 review: geometry

## Findings

1. **High — Distant shadow casters can panic the render.** `crates/paint/src/scene.rs:567` advances the shadow ray with `d.clamp(0.004 + 0.002 * t, 0.5)`. At distances above 248 m the lower bound exceeds the upper bound. Those distances are valid in the world model. **Evidence:** a block at depth 310 m under a 1° sun makes `World::cast([0,0,10], [0,1,0])` panic: `min = 0.5910787, max = 0.5`, exit **101**. See `check.rs`, case `cast`, and `scene-confirmed.log`. **Suggested fix:** cap the minimum step at the maximum step and add a distant-caster regression test.

2. **High — A distant cloud can make a foreground cloud disappear.** `crates/paint/src/atmos.rs:836–853,858–861` merges intersected cloud boxes into one interval, then takes only 64 uniformly spaced samples across it, including empty gaps. Adding a distant volume makes the spacing large enough to miss a foreground cloud entirely. **Evidence:** a cumulus at z=1000 m has alpha **0.9594534** at canvas (50,50). Adding a zero-density bank at z=50000 m changes it to **0.0**, even though that bank cannot contribute extinction. See `probe.rs` and `probe.out`. This undermines the cloud coverage described in `notes/atmosphere.md`. **Suggested fix:** march occupied intervals with a step bound that resolves each volume, rather than spending a fixed sample budget across empty gaps. Skipping zero-density volumes alone would not fix separated nonzero clouds.

3. **Medium — Overlapping bodies use incompatible local depths for visibility.** `crates/paint/src/scene.rs:826` passes world depth to `Form::add_at`, but `crates/paint/src/form.rs:874–879` selects the winner using `h.z` and only stores world depth afterward. Each body's synthetic form depth has its own projection scale. **Evidence:** two overlapping blocks anchored at 10 m and 10.1 m have visible surface depths **9.950003 m** and **9.6 m**. The view selects `Body(0)`, the farther surface, because its form z is −9993.965 versus −10040.242. See `check.rs`, case `order`, and `scene-confirmed.log`. **Suggested fix:** compare world depths for scene visibility, retaining form-space z separately for local shading and coordinate conversion.

4. **Medium — Sunk body surfaces remain visible below the waterline.** `crates/paint/src/scene.rs:781–787` clips a body only by comparing its depth with the ground/water ray's depth. It never rejects a surface whose world height is below the ground/water at that surface's location. With bodies projected at their anchor scale, these tests are not equivalent. **Evidence:** a block centered on level-zero water at depth 10 m is selected as `Body(0)` at canvas (501,505), with world point **[0.008284272, −0.09827561, 8.999998]**. The surface is nearly 10 cm underwater but still visible. See `check.rs`, case `waterline`, and `scene-confirmed.log`. **Suggested fix:** explicitly clip sunk geometry against the world surface, or use a consistent camera-ray intersection model for bodies and terrain.

5. **Medium — Reflection rays run backward beyond the backdrop.** `crates/paint/src/scene.rs:973–977` calculates `(backdrop - p[2]) / r[2]` without checking that the intersection is forward. Water can extend beyond the default 600 m backdrop. **Evidence:** water at approximately 1000 m returns `Mirror.travel = −400.0034` and a reflected point **[0, −0.8000063, 600]**, below the water, although the reflected ray points upward. See `check.rs`, case `mirror`, and `scene-confirmed.log`. **Suggested fix:** accept only positive backdrop intersections; otherwise use a forward sky/background fallback. Add a test beyond the backdrop.

6. **Medium — Sky lighting retains stale cached values after public parameter mutation.** `crates/paint/src/atmos.rs:158–177,346–347` exposes scattering parameters as mutable public fields but caches their derived dome radiance in a `OnceLock`. Builder methods invalidate it; direct field mutation does not. **Evidence:** create a 30° daytime sky, call `dome()`, then set `sky.sun` to −3°. Zenith radiance is **[0.0004568409, 0.0008217196, 0.0020605498]**, versus **[0.000108519125, 0.00013979716, 0.00025862284]** for a fresh −3° sky. The blue channel is nearly eight times brighter solely because of prior sampling. See `probe.rs` and `probe.out`. **Suggested fix:** use private parameters with invalidating setters, key the cache by its inputs or recompute. Test mutation after sampling.

7. **Medium — Worley returns incorrect nearest features and cell IDs.** `crates/paint/src/noise.rs:304–317` allows features anywhere within each cell but searches only a 3×3 neighborhood. Features two cell indices away can be nearer. **Evidence:** seed **15**, period **1**, point **(−0.029999733, 0.7669997)** returns F1 **1.1419679**, ID **3627889684**. A 7×7 search using the identical feature generator finds F1 **1.1241378**, ID **409115953**, feature **(1.0410368, 0.4255815)**. Seed 1 also returns an incorrect F2: **1.0763352** instead of **1.0659692**. See `noise_probe.out` and `worley_extra.rs`. Nearest-cell identity, cell randomness and edge distance can therefore be wrong. **Suggested fix:** expand the search or use cell-distance lower bounds to stop only when no unvisited cell can improve F2. Compare against a wider reference in tests.

8. **Medium — Transparent foreground foliage overwrites rear lighting.** `crates/paint/src/growth.rs:1438–1459`, especially **1451–1454**, replaces lighting whenever geometric coverage exceeds 0.5, without considering the clump's `fill`. Multiplication by the combined mask afterward cannot restore rear lighting. **Evidence:** a filled, lit rear clump has mask **1**, light **1**. Adding an identical foreground clump with `fill=0`, `lit=0` and greater z leaves mask **1** but changes light to **0**. This uses the public `Foliage::clumps` API. See `probe.rs` and `probe.out`. Partial-fill clumps follow the same overwrite path. **Suggested fix:** composite illumination with the same coverage/fill or leaf occupancy used for visibility; test transparent and partial-fill overlap.
