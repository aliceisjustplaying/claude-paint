# Viewer and space verification

Source commit: `4e525e50897807e9b5f734071dfeb330f1a393d3`. Follow [the verification protocol](README.md). All unrun rows are blocked, not failures. Browser passes below are agent-driven observations only and do not establish human verification.

## Fixtures and evidence

**B:** An isolated local studio server reading synthetic pi histories. Its basic two-look fixture is recorded in [browser evidence](evidence/browser.md). Extended rows need additional disposable fixtures: two painter folders, multiple sittings, explicit whole/crop/value/palette/reference looks, pending then completed tools and current painting source. Each row names needed additions. The fixture format and server launch follow the setup helpers in `studio/test_studio.py:20` and the server options at `studio/studio.py:625`. Python work uses uv and an existing or newly created virtual environment.

**S:** A disposable easel session with a canvas and a pile. Space examples start from `crates/easel/src/depth.rs:326`: world, body, upright depth layer and traced view. Commands run as separate chunks unless a row explicitly combines them. Comparisons use printed mask samples or before/after looks; reference-only invariants compare canvas pixels and painting clock. No source or real painter history is modified.

**Failure fixtures:** Request blocking/throttling happens only in the test browser or disposable server. Process termination, log editing and persistence-denial probes require dedicated throwaway sessions. Numeric stress rows need bounded resources and may remain blocked rather than risking the active server.
