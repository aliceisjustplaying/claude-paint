# Passages time verification

Each row is a separate assertion. A scenario can satisfy several rows in one execution, but each result is recorded independently. These instructions are a maintainer runbook, not a claim that they ran. “blocked — unrun” means no runtime result was collected, not that source reading failed. Shared interruption scenarios must use disposable state.

Recorded runtime results use the narrower aspect-5 fixture and exact inputs in [runtime passages evidence](evidence/runtime-passages.md). A pass establishes the row's stated claim through those recorded inputs; untested multi-part comparisons remain blocked—partial.

## Concrete fixtures

All fixtures use disposable roots at the documented source commit. No row inherits another row's result.

- **E:** an opened default-build session with no canvas and an empty painting log.
- **B:** E after `canvas{size=100,aspect=1,linen=12,ground={{pile={{"lead white",1}},um=40,apply="knife"}}}`; then `p=pile{{"red earth",1}}; m=rect(400,400,200,200)`. Save a baseline image, log and `print(wait(0))` before each independent case. Fresh copies mean replaying identical setup in separate roots, not painting repeatedly on one changing canvas.
- **W:** `work(m,{pile=p,hand="body",coverage=1,seed=7})`. An indicated option replaces or augments this table; never duplicate a key. For blend, omit pile and use `blend(m)`.
- **V:** B with `work(m,{pile=p,hand="body",coverage=2,clip=true,seed=7})`. Verify the sampled center actually contains open paint. If it does not, create a thicker fresh patch and record the exact fixture. Save this baseline before comparisons.
- **D:** V aged by bounded explicit waits until `drying(500,500)` and a grid of points across the painted region all report dry. Record all waits and save the dry image. Dry blending tests never substitute an unpainted ground or an unconfirmed elapsed-time guess.
- **G:** a calibrated, bounded Lua-only loop that occupies the session for several seconds without painting or advancing simulated time. Record loop count and prove completion below the live deadline in a disposable control first. A timing/admission barrier must establish that a request is queued or running; mere client launch does not prove either.
- **F:** a file-input chunk containing G followed by the exact operation named in the row. Confirm admission and file read completion before changing the file or queuing another command. Compare with an identical unmodified control. The later caller cannot alter a Lua local captured in accepted source.
- **L:** a calibrated long-passage fixture requiring more than 30 minutes of simulated hand time but bounded wall time. A diagnostic observation or existing engine test fixture must expose intermediate aging boundaries; output minute strings alone cannot establish exact slices. Record workload, diagnostics and resource limits before running.
- **Q:** 17 globals `p1` through `p17`, made in order with distinct mixtures `pile{{"lead white",i},{"red earth",18-i}}` for i=1..17. Verify the resulting palette colors are distinct so ledger deduplication cannot invalidate the case. Capture high-resolution tally/clock evidence through an existing diagnostic fixture because rounded day/time cannot distinguish 2.5 from 20 seconds. Use a held brush prepared before the measured reload.
- **R:** a separate bare-canvas session for maximum-duration waits. Establish memory, CPU and wall-time limits and an independent process monitor first. The request advances simulated time, but extreme aging can still be expensive. An exceeded resource limit is blocked, not a successful boundary result. Each boundary input is separate; the cumulative-limit row explicitly uses two successful calls.
- **Space fixture:** the concrete foreground/background occlusion setup in the space verification checklist, with its exact view and depth expressions recorded. Until that fixture is available, related rows stay blocked.
- **Fault fixture:** disposable process with a controlled barrier before persistence or a narrowly denied log/witness write. Preserve baseline bytes and record exact injection point. Do not infer storage-failure behavior by raising an ordinary Lua error.
