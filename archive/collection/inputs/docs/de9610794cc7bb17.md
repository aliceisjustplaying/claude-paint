# Control experiment: a Friedrich in plain Python (branch r7-python)

This project (claude-paint) is a large physical oil-paint simulator in
Rust. You are NOT using it. Your job is a control experiment that asks:
could a much simpler, look-first program paint a better Friedrich?

The inspiration for the project, in its author's words: "for the past few
months i've been asking our models to paint. opus 5.5 is very skilled at
emulating different styles. every image here is a python program
generated pixel by pixel. there is no image model, and no off-the-shelf art
software. instead, it's about 7,500 lines of code using standard libraries
to emulate different brush styles. the agents don't use any pictures as
reference, instead working only from what they know about each painter."

Do exactly that, for Caspar David Friedrich (1774–1840): write one Python
program that paints one new, original painting in his manner, pixel by
pixel. Subject, composition and format are your choice.

## Rules
- **No pictures.** Work only from what you know about Friedrich: his
  materials, method, habits of hand, recurring motifs and compositions.
  Never look at or search for images of his (or anyone's) paintings, and
  don't copy a known painting. You may read the text notes
  notes/friedrich.md, notes/briefs/friedrich_painter.md and
  notes/research/*.md in this repository for knowledge about him.
- **No image model, no art software.** Python with the standard library
  plus numpy (and Pillow only to write PNG files). No drawing libraries,
  no filters from image libraries (no PIL ImageFilter, no OpenCV, no
  scipy.ndimage blurs): write any brush, blur or texture yourself. Use
  `uv` with a virtual environment in your worktree (`uv init`, `uv add
  numpy pillow`).
- **Look-first is allowed and expected.** Unlike the main project, you
  don't have to simulate paint physics; emulate how his paintings look
  and how his brush marks look, however you think best. Don't read the
  Rust engine's code (crates/): this is an independent attempt.
- **Don't look at the project's own paintings** (notes/lab*, notes/paint1,
  notes/loops, notes/amnesia*): stay independent.
- The judge, Alice, looks at the whole and then zooms in at 3200px wide.
  Her yardstick: "less digital, more bad painter": a picture that looks
  like a person painted it with a brush beats one that looks rendered.
  Clean perfect gradients, hard even edges, repeated stamps and uniform
  noise read as digital.

## Setup
- Worktree ~/src/a/claude-paint-r7-python, branch r7-python. Put
  everything under `experiments/python_friedrich/` (the program, its
  pyproject, the notes). Commit often; don't push.
- Scratch: `~/.local/bin/agent-tmp pyfriedrich`; export TMPDIR=TMP=TEMP
  there. Never /tmp. Wrap long runs in `timeout`.
- View your output only as downscaled JPEG previews you make yourself
  (e.g. Pillow resize + save quality 95, subsampling=0), max 1000px: full
  PNGs are huge.
- Budget about 2 hours of work, as a person would take one sitting.
  Aim for about the OP's scale or less (a few thousand lines at most).

## Deliver (commit)
- The program; it must render deterministically (fixed seeds) at 1000px
  and 3200px wide: `uv run paint.py --width 3200 --out ...`.
- `experiments/python_friedrich/out_1000.png` and `out_3200.png` (lossless;
  commit both even though they're large).
- `experiments/python_friedrich/NOTES.md`: what you painted, how the
  program works (brush emulation, layers), what you think works and what
  doesn't, time spent, line count.
- Final reply: the painting's title, paths, line count and an honest
  self-assessment.
US English, no Oxford comma. The project is published under the pseudonym
"alice": never write the user's real name or an absolute home path into
committed files.
